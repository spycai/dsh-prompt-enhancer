# 许愿式提词升级方案（Wish-Mode）

目标版本：v2.0 → v2.1
基线版本：dsh-prompt-enhancer v1.5.4
编写日期：2026-11-14

---

## 0. 问题定义

### 0.1 现状（v1.5.4）

当前插件已解决"把草稿改写成专业提示词"，规则见 `lib/prompt.js:80` 的 `SYSTEM_PROMPTS.rewrite`：

- 规则 4「DECIDE, DO NOT INTERROGATE」：技术细节由模型自行决定，标注 `[默认：…，可改]`
- 规则 5：`[请补充：…]` 最多 2 个，仅限用户私有事实
- 规则 10：结果必须可直接发送

这套规则已经能处理"中等模糊"的输入，例如"帮我写个爬虫抓某网站"。

### 0.2 缺口

真实用户在 v1.2 版本曾遇到输出被 `[请补充：…]` 占满的问题，说明模型对"模糊度"的判断不稳定。而当输入极端模糊时（如「做个PPT」），当前单轮改写只能做**一次性猜测**：

1. 猜错了没有任何补救机会 —— 用户只能重新点，重新猜
2. 没有任何机制记住"上次这个用户接受/拒绝了什么"
3. 无法区分"用户懒得不写"和"用户真的不知道自己想要什么"

### 0.3 许愿式的定义

> 用户输入一句模糊短句，插件**主动补齐专业细节**，在**必要时做最小化提问**，最终交付一份用户能直接发给 AI、且拿到的结果符合其真实心愿的提示词。

三个硬约束：

- **不阻塞**：任何情况下都必须能产出可发送的提示词，追问不能成为必经关卡
- **不甩锅**：不能把专业判断推给不懂专业的用户
- **不重复**：同一个用户问过的偏好，下次不再问

## 1. 功能设计

### 1.1 总体架构：两段式生成

放弃"一次调用完成改写"，改为两段，中间用结构化数据连接。

```
用户草稿
   │
   ├─► [Pass 1] Analyze（分析器）
   │      输出：意图 + 槽位表 + 模糊项 + 置信度
   │      纯 JSON，可缓存、可复用、可单测
   │
   ├─► [决策层] 追问策略引擎（本地规则，不调模型）
   │      决定：问什么 / 问几个 / 用什么形式 / 用什么默认值
   │
   ├─► [用户交互，可选] Chips 追问条
   │      非阻塞，可直接发送 = 全部采用默认
   │
   └─► [Pass 2] Compose（合成器）
          输入：槽位值（用户答案 + 偏好记忆 + 默认值）
          输出：最终提示词
```

**为什么分两段**（关键工程理由）：

| 好处 | 说明 |
|---|---|
| 可缓存 | 同一草稿重复点击只跑 Pass 2 |
| 可测 | Pass 1 输出 JSON，可以用断言测试槽位抽取准确率 |
| 可插拔学习 | 槽位值是结构化字段，便于统计"用户常改哪个槽" |
| 失败可降级 | Pass 1 失败 → 直接退化为 v1.5.4 单轮模式，不报错 |

### 1.2 槽位模型（Slot Schema）

这是整个方案的骨架。槽位定义放在 `lib/slots.js`（新增）。

```js
// 槽位定义：每个槽位声明它属于哪一类、谁有权决定
export const SLOT_KINDS = {
  INTENT:    'intent',     // 用户想干什么 —— 必须从原文推断，不问
  DELIVERABLE: 'deliverable', // 交付物形态（PPT/文档/代码/表格）
  DOMAIN:    'domain',     // 领域/行业
  AUDIENCE:  'audience',   // 受众
  SCOPE:     'scope',      // 范围边界
  FORMAT:    'format',     // 格式、篇幅、结构
  TECH:      'tech',       // 技术栈、工具、平台
  CONSTRAINT: 'constraint',// 硬约束（时间、预算、已有素材）
  PRIVATE:   'private',    // 只有用户知道的事实（日期、账号、数据）
}
```

每个槽位带 **可问性（askability）**，这是追问机制的核心判据：

```js
{
  key: 'audience',
  kind: 'audience',
  question: '这份 PPT 讲给谁看？',
  options: [
    { label: '公司内部同事', value: 'internal-colleagues' },
    { label: '客户 / 甲方',   value: 'clients' },
    { label: '领导汇报',     value: 'management' },
  ],
  default: 'internal-colleagues',
  askability: 'ask',        // ask | never | if-missing
  costToAnswer: 'low',      // low | medium | high —— 用户回答成本
  impact: 'high',           // 答错对成品的影响：high | medium | low
  source: 'user-only',      // user-only | inferable | decidable  —— 决策依据
}
```

### 1.3 追问机制（核心）

#### 1.3.1 什么该问：四象限判定

槽位按 `source` × `impact` 落格，**只有右上角才问**：

| | impact: high（答错毁成品） | impact: low（答错无伤） |
|---|---|---|
| **source: user-only**（只有用户知道） | ✅ **必须问**（但给默认） | ⚠️ 不问，直接用默认 |
| **source: decidable**（专业上可判断） | ❌ **绝不问**，自己决定 + 标注 | ❌ 不问，静默决定 |
| **source: inferable**（能从上下文推断） | ❌ 不问，按推断结果 | ❌ 不问 |

**判定依据**：`source` 由 Pass 1 的模型预测，但**必须过一遍本地白名单校验**（`canAsk()`），防止模型擅自把专业问题抛给用户：

```js
// lib/ask-policy.js
const ASKABLE_KINDS = new Set(['audience', 'private', 'constraint'])

export function canAsk(slot, policy) {
  if (policy === 'off') return false
  if (slot.source !== 'user-only') return false      // 专业问题一律不问
  if (!ASKABLE_KINDS.has(slot.kind)) return false    // 只允许问这几类
  if (slot.costToAnswer === 'high') return false     // 回答成本高 → 给默认
  if (slot.confidence >= 0.8) return false           // 已经很确定 → 不问
  return slot.impact === 'high'
}
```

这是**双保险**：模型提建议，本地规则否决。避免 v1.2 那种"模型把技术选型拿出来问用户"的退步。

#### 1.3.2 问几个：预算控制

```js
export const ASK_BUDGET = {
  maxQuestions: 3,      // 硬上限，配置项可调 0-3
  maxRounds: 1,         // 只问一轮，不连环追问
  minConfidenceToSkip: 0.8,
}
```

超过预算的槽位 → 一律降级为「默认 + 标注」，写法沿用现有规则 4：
`[默认：面向公司内部同事，可改]`

#### 1.3.3 怎么问：Chips 而非弹窗

交互形态**必须是可忽略的、预填的、一键可改的**，不能是表单弹窗。

```
┌──────────────────────────────────────────────────────┐
│  舒服                                                  │
│                                                       │
│  ┌─────────────┬─────────────┬─────────────┐         │
│  │ 受众：同事 ▾ │ 页数：10 ▾  │ 风格：简洁 ▾ │  跳过 › │
│  └─────────────┴─────────────┴─────────────┘         │
│                    ↑ 每项已预选默认值，点一下换        │
│  ╭──────────────────────────────────────╮            │
│  │ 发送                        [✨]      │            │
│  ╰──────────────────────────────────────╯            │
└──────────────────────────────────────────────────────┘
```

设计要点（逐条对应"不阻塞"约束）：

| 要求 | 实现 |
|---|---|
| 不弹窗 | 在 composer 内部渲染一条 chip 行，不遮罩、不抢焦点 |
| 已有默认 | 每个 chip 预显示默认值，用户不改就是接受 |
| 可一键跳过 | 右侧「跳过」= 全部采用默认并立即改写 |
| 可直接发送 | 用户直接点发送 → 视为全部默认，正常走改写 |
| 不重复问 | 答案写入偏好记忆，下次同槽位不再问 |

#### 1.3.4 用户不回答怎么办：三级回退

这是方案里最需要明确的部分。

**回退链（严格按顺序）：**

```
Level 1  用户偏好记忆（Profile）
            ↓ 没有记录
Level 2  领域默认策略（Domain Defaults）
            ↓ 领域未知
Level 3  通用最保守默认（Generic Default）
            ↓
        一律标注 [默认：…，可改]，不抛 [请补充]
```

具体规则：

| 情形 | 处理 |
|---|---|
| 用户点了「跳过」 | 全部走回退链，立即生成 |
| 用户 30 秒无操作 | **不自动继续**（避免打断思考），但输入框占位提示「不改也能发送」 |
| 用户直接按发送 | 全部走回退链，正常生成 |
| 用户只回答了部分 | 已答的用答案，未答的走回退链 |
| Pass 1 分析失败 | 整体退化为 v1.5.4 单轮模式，不显示追问条 |
| 追问后模型超时 | 保留追问条状态，返回错误，允许重试，不丢答案 |

**关键约束：任何路径下，`[请补充：…]` 的出现总数仍 ≤ 2**，且只能用于真正的私有事实（如"公司名称"）。这条是 v1.2 教训的直接固化，写进 Pass 2 的系统提示词。

#### 1.3.5 领域默认策略库

`lib/domain-defaults.js`，按识别出的领域提供默认槽位值。首批覆盖 6 个高频领域：

| 领域 | 触发词 | 典型默认 |
|---|---|---|
| PPT / 汇报 | PPT、幻灯片、汇报、宣讲 | 受众=内部同事；页数=10±3；风格=简洁商务；含封面+目录+正文+总结 |
| 文档 / 方案 | 方案、文档、报告、计划书 | 结构=背景/目标/方案/风险/排期；篇幅=1500-3000 字 |
| 代码 / 脚本 | 爬虫、脚本、工具、自动化 | 语言=按上下文推断；含错误处理+运行说明 |
| 数据分析 | 分析、统计、报表、图表 | 输出=结论先行+图表+口径说明 |
| 文案 / 内容 | 文案、推文、公众号、宣传 | 调性=专业不浮夸；含标题备选 3 个 |
| 学习 / 解释 | 解释、教我、入门、怎么学 | 从零讲起；含类比；含可执行练习 |

这份库是**纯数据**，可热更新，不需要改代码。也是社区贡献的天然入口。

### 1.4 记忆与自我学习

#### 1.4.1 三层存储

```
L1  单轮缓存（内存）
      同一草稿 + 同一模式 → 直接返回上次结果，TTL 5 分钟
      ↓
L2  会话记录（JSONL 追加写）
      ~/.dsh/prompt-enhancer/history.jsonl
      每条：草稿、输出、模式、槽位值、用户行为、时间
      ↓
L3  偏好画像（聚合 JSON）
      ~/.dsh/prompt-enhancer/profile.json
      从 L2 定期归并出的稳定偏好
```

#### 1.4.2 L2 记录结构

```json
{
  "id": "01HXY...",
  "at": "2026-11-14T02:30:00.000Z",
  "mode": "wish",
  "input": "做个PPT",
  "inputLen": 5,
  "output": "...",
  "outputLen": 820,
  "slots": {
    "deliverable": "pptx",
    "audience": "internal-colleagues",
    "pages": 10,
    "style": "concise-business"
  },
  "asked": ["audience", "pages"],
  "answered": ["audience"],
  "defaulted": ["pages"],
  "provider": "deepseek",
  "model": "deepseek-chat",
  "score": null,
  "feedback": {
    "sent": true,
    "editedBeforeSend": false,
    "undone": false,
    "charsChanged": 0
  }
}
```

#### 1.4.3 学习信号（这是能不能真学到东西的关键）

**不用模型自评，只用真实行为。** 五个信号，按强度排序：

| 信号 | 采集点 | 权重 | 含义 |
|---|---|---|---|
| **直接发送且未编辑** | 发送时对比草稿与改写结果 | +2 | 强正：完全接受 |
| **发送前有编辑** | 统计 diff 字符数 | +1（按比例） | 半正：方向对，细节要调 |
| **点了 ↩ 恢复** | client.js 现有 undo 逻辑 | −2 | 负：不接受 |
| **同一意图反复改写 ≥3 次** | L2 里相似 input 聚类 | −1 | 负：前几次都不满意 |
| **追问时总选同一项** | chips 选择记录 | +1 | 强化该槽位默认值 |

采集方式：client 端在以下时机上报 `/api/prompt-enhancer/feedback`：

- 用户编辑了改写结果 → `editedBeforeSend: true` + 编辑距离
- 用户点了 undo → `undone: true`
- 用户把改写结果发出去了 → `sent: true`

#### 1.4.4 L3 画像生成规则

每天首次启动或累计满 20 条新记录时，跑一次归并（纯本地计算，不调模型）：

```js
// lib/profile.js
export function foldProfile(records) {
  const out = { slots: {}, domains: {}, updatedAt: new Date().toISOString() }
  for (const r of records) {
    if (r.feedback.undone) continue                      // 被撤销的样本丢弃
    const w = r.feedback.editedBeforeSend ? 0.5 : 1      // 编辑过的降权
    for (const [k, v] of Object.entries(r.slots ?? {})) {
      const stat = (out.slots[k] ??= {})
      const cur = (stat[v] ??= { score: 0, count: 0 })
      cur.score += w
      cur.count += 1
    }
  }
  return out
}
```

画像的**唯一用途**：填回退链的 Level 1。它是"软偏好"，不是硬规则 —— 置信度不足（样本 < 3）时不使用。

#### 1.4.5 few-shot 注入（真正的"自我进化"）

除了偏好，还把**历史上用户直接发送、未编辑的高分样本**作为 few-shot 注入 Pass 2 的系统提示词。

```js
// lib/examples.js
export function pickExamples(records, intent, limit = 3) {
  // 1. 只取 feedback.sent === true && !editedBeforeSend && !undone
  // 2. 按意图相似度排序（简单方式：领域关键词重合度；后续可换向量）
  // 3. 同意图最多 1 条，避免样本同质化
  return ranked.slice(0, limit)
}
```

这等价于 DSPy 的 BootstrapFewShot 思路（用成功样例构造演示），但**不需要训练、不需要 Python**。注入位置在 system prompt 末尾：

```
Here are examples of drafts this same user accepted before. Match their level of detail and style:
<example>…</example>
```

**注**：示例只注入**用户自己**的历史，不跨用户，避免隐私与风格污染。

#### 1.4.6 隐私与开关

| 项 | 处理 |
|---|---|
| 存储位置 | 本地 `~/.dsh/prompt-enhancer/`，不上传 |
| 存什么 | 草稿全文、输出、行为信号 |
| 不存什么 | 附件内容、@引用的文件内容、模型凭证 |
| 开关 | `historyEnabled` 配置项，默认 `true`；关掉即完全不落盘 |
| 清理 | 卡片内提供「清空历史」，一键删 history.jsonl + profile.json |
| 上限 | `historyMaxRecords`，默认 500 条，超出按时间淘汰 |

在 `buildConfigSchema()`（`lib/prompt.js:125`）追加：

## 2. 交互流程

### 2.1 主流程（有过追问）

```
1. 用户输入「做个PPT」                      [composer]
2. 点击 ✨
3. Pass 1 分析（约 1-2s）                    [按钮转圈]
4. 判定：audience(source=user-only, impact=high) → 问
         pages(decidable)                        → 不问，给默认 10
         style(decidable)                        → 不问，给默认简洁
5. 渲染追问条：受众 [同事▾]  跳过 ›           [不阻塞，不抢焦点]
6. 用户点「客户」→ 立即触发 Pass 2
7. Pass 2 合成（约 2-4s）                    [按钮转圈]
8. 草稿被替换为完整提示词
9. 显示 ↩ 恢复（120s 内可撤回）              [沿用现有逻辑]
10. 用户发送 → 上报 feedback：sent=true, edited=false
```

### 2.2 无追问流程（最高频路径）

```
1. 用户输入「帮我写个脚本把Excel里重复行删掉」
2. 点击 ✨
3. Pass 1 判定：所有槽位 source ∈ {decidable, inferable} → 无追问
4. 直接 Pass 2 合成
5. 草稿替换 + ↩ 恢复
   总耗时与 v1.5.4 持平（一次额外调用约 +1s）
```

**优化**：当 Pass 1 判断 `confidence > 0.9` 且无可问槽位时，跳过追问条渲染，**直接在同一请求内完成 Pass 1 + Pass 2**，避免两次网络往返。这是常见的快速路径。

### 2.3 跳过流程

```
1. 追问条出现
2. 用户点「跳过 ›」
3. 全部槽位走回退链填充
4. 直接 Pass 2
5. 追问条收起，显示「已用默认设置」
```

### 2.4 失败与降级

| 失败点 | 行为 |
|---|---|
| Pass 1 超时/返回非法 JSON | 静默降级为 v1.5.4 单轮改写，无提示（用户无感） |
| Pass 1 返回但槽位为空 | 同上 |
| Pass 2 超时 | 显示「提示词服务未就绪」类错误，保留追问条答案，可重试 |
| 历史写入失败 | 记 console.warn，不阻塞主流程 |
| 画像读取损坏 | 视为空画像，不阻塞 |

## 3. 提示词改写质量评估标准

### 3.1 六个评估维度

每个维度必须**可判定**，不能是"感觉不错"。

#### D1 可发送性 (Sendability)

- **定义**：用户不做任何补充，直接把结果发给 AI，能否得到有用回复
- **判定依据**：`[请补充：…]` 的数量与位置
- **通过阈值**：`请补充` 计数 ≤ 2，且不含"目标/交付物/受众"这三类关键槽位
- **自动化**：✅ 正则计数，可在 CI 跑

#### D2 结构完整性 (Completeness)

- **定义**：必需槽位覆盖率
- **判定依据**：五类必备槽位是否都有明确表述 —— 目标 / 交付物 / 格式 / 约束 / 受众
- **通过阈值**：覆盖率 ≥ 4/5（80%），且"目标"与"交付物"必须 100% 存在
- **自动化**：✅ 关键词 + 槽位比对

#### D3 事实保真 (Fidelity)

- **定义**：原文中的具体事实不被篡改、不丢失
- **判定依据**：抽取原文实体（数字、日期、人名、URL、`@mention`、文件名），检查输出中是否保留
- **通过阈值**：实体保留率 **100%**，零篡改（数字变了即失败）
- **自动化**：✅ 正则抽取 + 集合比对，这是最硬的一条，可完全自动化
- **注**：现有 `preserveMentions()`（`lib/prompt.js:270`）已覆盖 `@mention`，需扩展到数字/日期/URL

#### D4 非专业用户可用性 (Novice-usable)

- **定义**：不懂行的人能否看懂并照做
- **判定依据**：
  1. 每个专业决策是否带了 `[默认：…]` 标注（覆盖率 100%）
  2. 是否出现"未经解释的术语"（维护一份术语黑名单 + 人工抽查）
- **通过阈值**：默认标注覆盖 100%；术语密度（未解释术语数 / 总句数）≤ 0.15
- **自动化**：⚠️ 半自动（标注覆盖可自动，术语需词表）

#### D5 无冗余 (Concision)

- **定义**：不注水，不为凑结构而堆通用套话
- **判定依据**：
  1. 长度比 `len(output) / len(input)`
  2. 命中 boilerplate 黑名单（如"作为一个AI""请务必""综上所述""这是一个很好的问题"）
- **通过阈值**：单句请求的长度比在 8–80 之间（对应"一句话 → 一段话"）；命中黑名单 = 直接失败
- **自动化**：✅ 纯规则

#### D6 意图一致 (Intent Fidelity)

- **定义**：改写后的目标与用户原意一致，不跑偏、不擅自扩题
- **判定依据**：人工抽样 + LLM-as-judge 双评，判定"改写后的任务是否等同于原任务"
- **通过阈值**：抽样一致率 ≥ 95%
- **自动化**：❌ 需抽样人工，用 LLM 预筛争议样本

### 3.2 评分卡

每次改写算一个 0-100 分，用于回归监控：

```
score = 25·D3(保真, 二值) + 20·D6(意图, 0/1) + 20·D2(完整性) + 15·D1(可发送) + 12·D4(可用性) + 8·D5(无冗余)
```

D3 和 D6 权重最高，因为**它们错了整个改写就是负价值** —— 保真错了等于篡改用户需求，意图错了等于答非所问。

### 3.3 评估数据集

建 `test/fixtures/wish-cases.json`，至少 40 条，覆盖：

| 类别 | 条数 | 示例 |
|---|---|---|
| 极短愿望 | 10 | 「做个PPT」「写个方案」「分析下数据」 |
| 中等模糊 | 10 | 「帮我写个爬虫」「做个员工管理系统」 |
| 含私有事实 | 8 | 「下周给客户演示，做个PPT」（日期+受众已给） |
| 多实体需保真 | 6 | 含数字/日期/URL/@引用 |
| 陷阱：不该问 | 6 | 「用React写个TODO」，技术栈已给，不能反问 |

每条给定期望行为（应问哪几个槽、不应问哪几个、必须保留哪些实体）。

### 3.4 CI 门禁

```yaml
# .github/workflows/verify.yml 追加
- 跑 D1/D2/D3/D5 自动断言（纯规则，不需要真调模型）
- D3 保真失败 → 直接 fail，不允许合并
- 平均分低于 v1.5.4 基线 → fail
```

### 5.3 风险与对策

| 风险 | 概率 | 影响 | 对策 |

| Pass 1 增加一次调用，感知变慢 | 高 | 中 | 快速路径合并两段；Pass 1 用更小 maxTokens（512）；结果按草稿 hash 缓存 5 分钟 |
| 模型不遵守 JSON 输出 | 中 | 高 | 强约束 + 本地重试 1 次 + 失败即降级到单轮，绝不报错给用户 |

| 历史记录变慢/膨胀 | 低 | 中 | 硬上限 500 条；归并后压缩旧记录为统计值 |
| 评估集过拟合 | 中 | 中 | 留 30% 作 hold-out；每次改提示词都跑全量 |
| 跨 DSH 版本 API 变动 | 中 | 高 | 沿用 v1.5.4 的 `ctx.inject` 模式；新增服务全部走 `inject` |

## 6. 关键设计决策记录（ADR 摘要）

| 决策 | 理由 | 被否方案 |
|---|---|---|
| 两段式生成 | 可缓存、可测、可插拔学习 | 单次调用内完成（无法单独优化追问） |
| 追问用 chips 不用表单 | 不阻塞、有默认、可跳过 | 弹窗表单（打断流程，非专业用户会卡住） |
| 本地规则否决模型提问 | 防止模型再次把技术选型抛给用户（v1.2 教训） | 完全信任模型判断 |
| 学习用 few-shot 不用微调 | 无需训练设施，隐私本地化 | 微调（成本高，跨用户隐私风险） |
| 信号只用真实行为 | 模型自评不可靠 | LLM-as-judge 打分当作学习信号 |
| 沉默 30 秒不自动继续 | 用户可能正在思考，自动继续会打乱 | 超时自动生成（抢跑） |
