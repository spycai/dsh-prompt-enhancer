## v1.9.5

按 v1.9.4 缺陷审计报告修三条。**未推送。**

### P0 layout 改为 reactive 捕获

原代码 `layoutService = ctx.get('layout')` 是**一次性探测**——若布局服务在 apply 时
未就绪，句柄永远为 null，「切回对话」按钮静默失效。

这与本项目自己在 `index.js:114-119` 写下的警告直接冲突：那段注释说明 Host 路由
必须用 `ctx.inject([...])` 而不能用 `ctx.get()` 探测，因为探测会和启动顺序竞争。

改为 `ctx.inject(['layout'], cb)`：服务就绪时回调。声明写在调用内部，
**不影响插件激活对 layout 的依赖**。

### P1 鉴权改为 fail-closed

两处 Node 路由原本是：

```
const connection = ctx.get('connection')
if (connection !== undefined) { …鉴权… }   // ← 服务缺失则整段跳过
```

服务不可用时鉴权被完全绕过、请求直接放行——**安全默认方向反了**。
改为抽取 `admitNodeRequest`：拿不到 `connection` 就直接 401。

顺带消除两段逐字重复的鉴权代码（P2），以后加路由不会再复制。

### P1 补测试堵盲区

审计发现 `selectPanel` 在渲染测试中出现 **0 次**——整条跳转链路从未被执行验证过，
又是「契约测试证明代码写了，行为测试证明它真的跑了」这个老问题。

新增：
- 冒烟测试断言 `layout` 通过 `ctx.inject` 声明，且**不在**激活依赖里
- `layout` 句柄读取抛错时不拖垮插件
- `test/admit.test.mjs`（6 条）：服务缺失、`ctx.get` 抛错、admission 拒绝、
  `admit` 抛错、正常放行、无 rejection 字段视为放行

### 仍需真机确认

`selectPanel('conversation')` 在真实 DSH 里是否接受这个 id——依据是 slot 注册键
`"already taken: conversation"`，但那不等于该方法的合法入参。测试设施无法覆盖，
保留为待验证项。

## v1.9.4

**修复：点「回填到输入框」后看不到内容，以为没有地方输入。**

### 原因

面板是独立的 `main` slot，**和对话输入框不在同一个视图**。`setDraft` 确实把文本
写进了 composer，但用户还在面板里，屏幕上没有任何变化——也没有任何提示告诉他
「东西已经写过去了」。

这不是 bug，是设计缺口：操作发生的界面和结果所在的界面不在一屏。

### 修复

- 用 `ctx.get('layout')` 捕获布局服务，新增 `goToConversation` 调
  `selectPanel('conversation')` 切回对话
- 回填后显示明确提示：「已写入对话框，只是当前面板看不到它。」+「切回对话 →」按钮
- 新结果到达时重置该提示

### 关键：为什么用 ctx.get 而不是 inject

`inject` 会让插件激活依赖该服务存在。切换视图只是便利功能，服务缺失时应该退化为
「按钮点了没反应」，而不是「插件加载失败」。所以用 `ctx.get` 包 `try` 捕获——
这和之前 `profileDir` 那个坑是同一类问题，已加测试锁住。

### 验证

- 330 条测试（v1.9.3 为 327 条）
- 新增：`ctx.get` 抛错时插件仍注册、layout 缺失时面板仍渲染
- 质量门禁 55.9 vs 51.6，无回退

**未推送**（按用户要求，等待批准）。

## v1.9.3

面板视觉与交互优化。**只改样式，JSX 一行未动。**

### 为什么不改 JSX

面板组件有 946 行，其中 30+ 个 state 与 handler。全量重排会重引入 v1.9.2 那类
初始化顺序风险，而视觉收益完全可以靠换样式拿到。

关键前提：面板用了 **28 个 CSS 类，与 JSX 一一对应**。保持类名不变、只替换
`STYLE` 里的字符串内容，视觉全变而引用关系零改动。

### 五项改动

1. **层级**：标题提到 18px/600 并收紧字距；旧名提示从「带边框的方框」降为 11px
   引注（左侧 2px 淡竖线），不再与标题争视觉重量
2. **间距节奏**：从所有区块统一 16px，改为 4/6/10/12/22 阶梯——区块间 22px，
   组内 10px，label 与控件 6px
3. **按钮主次**：主按钮实底加重；ghost 平时无边框、hover 才出淡底；
   选中态用主色描边 + `bg-layer-2` 底
4. **条目重心**：元数据（来源/许可）降到 11px 并降不透明度；正文两行截断，
   让标题重新成为焦点
5. **状态行可见**：从 11px 提到 12px，行高加大

### 两处刻意偏离原方案（可靠性优先）

- focus 环用 `outline` 而非 `box-shadow: … color-mix(…)`：若 `color-mix`
  不被支持，整条 `box-shadow` 声明会被丢弃，键盘用户失去焦点提示
- 选中底色用已有的 `bg-layer-2` + 主色描边，同样不依赖 `color-mix`

### 窄宽度

所有 flex 容器补 `flex-wrap`；输入类加 `flex:1 1 130px; min-width:0`
（`min-width:0` 是关键，否则 flex 子项不会收缩、直接溢出）。

### 验证

- 327 条测试全过，含 5 条渲染冒烟
- 质量门禁 55.9 vs 51.6，无回退
- 类名完整性核对：JSX 使用的 30 个类在样式里全部有定义，零缺失
- `dsh-pe-*`（面板外按钮）与 `].join('')` 未被触碰

## v1.9.2

**修复：点插件入口进不去界面。** v1.9.1 引入的回归。

### 原因

`zh`（判断是否中文）声明在组件靠后的位置，而 v1.9.1 新增的 `appliedLabels`
与 `savePreset` 在它之前就读取了它。`const` 的暂时性死区直接抛
`ReferenceError: Cannot access 'zh' before initialization`，
**整个面板组件渲染失败，表现为点入口没反应**。

修复：把 `zh` 的声明移到组件顶部，所有消费者都能看到已初始化的值。

### 为什么 322 条测试没抓到

因为此前所有针对 client.js 的断言都是**文本检查**——只证明函数名拼写正确、
契约存在，从不证明它**能跑**。

新增 `test/client-render.test.mjs`：用 VM 加载真实 bundle，配一个最小 React
替身，调 `apply()` 捕获各 slot 注册的组件，然后**真的把面板组件调用一次**。
引用错误、错误的解构、对 undefined 的方法调用，从此会在测试里失败，而不是在
用户的入口上失败。

**并验证了这个测试真的有效**：把 `zh` 声明还原到末尾构造反向用例，
冒烟测试如期抛 `Cannot access 'zh' before initialization`。
一个抓不到 bug 的测试等于没写，所以这一步必须做。

### 验证

- 327 条测试（v1.9.1 为 322 条），新增 5 条渲染冒烟测试
- 质量门禁 55.9 vs 51.6，无回退

## v1.8.8

按「生成之后那一段」的思路补齐四项能力。**未推送。**

前三个版本都在修「生成之前」和「生成失败」，但拿到结果之后仍有三个摩擦点：占位符要自己找、
不满意只能重来、好的存不下来。

### 1. 占位符变表单

生成结果里的 `[请补充：…]` 之前只写在后端规则里，前端零处理——用户得复制出去自己找括号。

现在 Host 在响应里直接返回 `placeholders` 与 `missing`，面板渲染成带标签的输入框，
填完实时替换进正文，**复制和回填都用填好的版本**。

关键决定：**占位符识别放在 Host**，不是前端各写一份。Client 无法 import ESM，若在前端实现就是
审计刚指出的「重复实现」问题重演。

未填的空白保留原括号，不会在句子里留洞。相同的标签合并成一个输入框，填一次替换所有出现位置。

### 2. 结果微调

结果下方新增三个快捷按钮（再短一点 / 更正式 / 加硬性约束）和一个自由输入框。

技术上走 `refineOf`：把**当前结果**作为 `current_prompt` 数据块、调整要求作为
`change_request` 数据块，两者都用 nonce 标签包裹。所以是「编辑现有的」，不是「从想法重推」——
后者会把上一版做过的所有决定全部丢掉，「压到 8 页」会返回一份不同的提示词，而不是更短的。

微调后保留仍然存在的空白填写值，其余清空。

### 3. 存入我的宝库

结果区新增「存入我的宝库」，写到 `<profile>/.dsh-wish-tree/personal.json`。

- **和远程缓存分开存**：刷新只覆盖缓存，绝不动个人库
- 列表里**个人条目排最前**，因为这是唯一不能重新拉取的数据
- 相同正文拒绝重复存入（按两次保存通常是确认，不是想要两份）
- 上限 200 条；标题自动从正文首句派生，不弹命名对话框

### 4. 自检提示

结果下方显示「目标、格式、受众、约束都齐了」或「还缺：受众 / 主要约束」。

检查的是**输出**（生成出来的提示词），不是用户的输入——让人知道这份提示词弱在哪，而不是盲信。

### 验证

- 302 条测试（v1.8.7 为 266 条）：placeholders 18 + personal 13 + refine 集成 5
- 质量门禁 55.9 vs 51.6，无回退

- 真机重载：三条路由均 401（存在），缓存 148 条未受影响

## v1.8.5

修复 v1.8.4 之后仍然「刷新没东西」的问题。真实错误是
`cannot get property "profileDir" without inject`。

### 根因

`resolveProfileDir` 里写了 `ctx?.profileDir`，而 Cordis 里这些是**注入服务代理**——
未声明 `inject` 就访问会**直接抛异常**，不是返回 `undefined`。宝库每次请求都在这一行崩掉，
而数据一直好好躺在磁盘上。

（v1.8.4 把 `failureOutcome` 的通用兜底暴露成了 `The model call failed.`，误导了排查方向。）

### 修复

- 改用 `ctx.get(name)` 并全程包 `try`，不再访问任何 ctx 属性；拿不到就回退到
  `~/.dsh/profiles/desktop`。
- 两个 handler 全部包进 `try`（原来 `libraryPayload` 在 try 外，抛错变成未捕获拒绝）。
- 失败响应带 `error.name` 与 `message` 首行，不再被包成通用文案。
- 面板内联 34 条兜底种子，路由不通时也有内容可看，不再是空白。
- 加了用 Proxy 模拟注入代理的回归测试。

## v1.8.2

用户反馈：面板点「生成」后很久没有反应。

排查结论：**不是卡死，是模型慢**。当前用的 `hy4free` 在 profile 里声明为

但等待期零反馈是真实缺陷：按钮只显示「生成中…」，240 秒内没有任何变化，用户无法区分

- 按钮显示**已等待秒数**（`生成中… 12s`）
- 等待超过 30 秒时提示「该模型思考较慢且无法调快，可换模型或继续等待」
- 等待期间提供**取消按钮**
- 计时器仅在 `busy` 时运行，请求结束立即清理

### 建议

若追求速度，换非推理模型（如 DeepSeek 系列）；若坚持用推理模型，可试 `hy4std`
并把 `reasoningEffort` 设为 `low`（它支持 low，`hy4free` 不支持）。
