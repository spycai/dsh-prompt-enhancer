## v1.8.4

用户反馈：点「刷新」宝库没有东西。

### 根因

宝库路由**只有一条** /api/wish-tree/library，而改写路由一直有两条
（/api/... + /prompt-enhance）。当页面上下文打不通 /api/... 时，
宝库没有任何回退路径，而 .catch 是空的 —— 错误被完全吞掉，用户看到的就是空白。

面板的 `records` 初始值是 `[]`，所以 list 一失败，宝库直接是空的，连「没有匹配」
都算不上，就是「没有东西」。

### 修复

1. **加第二条路由** `/wish-tree-library`（webServer），与改写路由对齐，
   同样走 `connection.admit` 鉴权。
2. **前端探两路径**：新增 `postLibrary`，先试 `/api/...` 再回退，
   成功后记住可用路径。
3. **错误必须可见**：去掉静默 `.catch`，失败原因写进 `libNotice`
   （如「提示词宝库路由未响应（HTTP 404）」）。
4. **空态区分**：宝库完全没加载时显示「宝库没有加载成功 —— 请点「刷新」重试」，
   而不是误导性的「没有匹配的条目」。

### 验证

- 266 条测试（v1.8.3 为 265 条）
- 真机确认两条路由均在线（HTTP 401 = 需会话，路由存在）
- 缓存 149 条全中文
- 质量门禁无回退

## v1.8.3

用户要求：**只要中文提示词**，并且宝库要能**自动联网搜索精品提示词落库**。

核对后发现最初的要求只做到了一部分，且有一个从未暴露的真 bug。

### 改为纯中文宝库

- **移除英文源** `f/prompts.chat`（10.4 MB CSV）。中文用户看英文提示词正文没有价值，还挤占了列表。
- **25 条内置种子全部重写为中文**（原来是英文，对中文用户同样没用），标题、正文、标签都改。
- 数据源只保留 `Vipuser2023/chatgpt-prompts-chinese`（JSON，CC0-1.0，中文）。
- **语言闸门**：`mergeLibraries` 里统一过滤 `language !== 'zh'` 的记录，种子、远端点、磁盘缓存三条路径都过这一关。将来即使有人加回英文源，也不会漏进面板。
- 面板不再需要语言切换，列表里不会再出现英文条目。

### 落库（持久化缓存）

新增 `lib/library-cache.js`，缓存写到 `<profile>/.dsh-wish-tree/library.json`：

- **重启后自动读缓存**，不再退回 25 条种子（这是原设计最大的漏洞：拉到的全丢了）
- 带 schema 版本号，版本不符则丢弃而非误读
- 读写失败一律降级为「无缓存」，绝不让面板崩溃
- 只持久化**远端**记录，种子已编译进 bundle，不重复存

### 自动刷新

新增 `autoRefreshHours`（默认 6 小时，0 关闭）。启动 15 秒后检查一次，之后每 5 分钟检查一次，由缓存时间戳决定是否真的去拉。

`isRefreshDue` 此前是**死代码**——导入了但从未调用，所以「自动」从来没有实现过。

部分来源失败时用 10 分钟短间隔重试（`refreshDecision`），而不是干等 6 小时。

### 修掉一个从未暴露的 bug

**英文源 `prompts.chat` 从来没有成功拉取过一次。** 该文件 10.4 MB，而 `FETCH_LIMITS.maxBytes` 是 8 MB，每次都被 `too-large` 拒绝。所有测试用的都是短 mock CSV，所以从未暴露——源看起来健康，实际一直失败。上限提到 16 MB，并加回归测试断言「上限必须大于最大真实负载」。

### 面板可见性

宝库顶部显示「共 N 条 · 刚联网更新/已缓存/内置库 · 上次日期」，部分来源失败会点名是哪个源。

### 验证

- 265 条测试（v1.8.2 为 232 条），新增 33 条
- 质量门禁 55.9 vs 51.6，无回退
- 真机联网验证：25 种子 + 149 中文远程 = **174 条，无一条非中文**

## v1.8.2

用户反馈：面板点「生成」后很久没有反应。

排查结论：**不是卡死，是模型慢**。当前用的 `hy4free` 在 profile 里声明为
`supportedEfforts: [high]`、`canDisableThinking: false` —— 只能以最高强度思考且无法关闭，
慢是模型自身限制，插件侧无参数可调。

但等待期零反馈是真实缺陷：按钮只显示「生成中…」，240 秒内没有任何变化，用户无法区分
「正在跑」和「已卡死」。

### 修复

- 按钮显示**已等待秒数**（`生成中… 12s`）
- 等待超过 30 秒时提示「该模型思考较慢且无法调快，可换模型或继续等待」
- 等待期间提供**取消按钮**
- 计时器仅在 `busy` 时运行，请求结束立即清理

### 建议

若追求速度，换非推理模型（如 DeepSeek 系列）；若坚持用推理模型，可试 `hy4std`
并把 `reasoningEffort` 设为 `low`（它支持 low，`hy4free` 不支持）。

### 验证

- 232 条测试（v1.8.1 为 230 条）
- 质量门禁 55.9 vs 51.6，无回退

## v1.8.1

用户提出「提示词开头是不是该加身份，例如『你是一位经验丰富的 PPT 视觉设计大师』」。

调研后判定**不建议默认加**：身份句不排除任何候选方案（横竖版、受众、页数一个都没决定），「大师」还容易诱导模型往视觉炫技走、牺牲「每页一个结论」；且它与本插件规则 9「不堆通用套话」以及评估器 D5（persona 免责声明直接判失败）冲突。基础系统提示词首行的 `You are a senior engineer...` 是对**改写器**说的，与「输出给用户的提示词开头」是两回事，保持不变。

改为提供两件可核验的替代能力：

### 宝库：3 条演示稿验收口径

- `seed-des-04` 编辑级验收清单（字号层级 ≤3、每页一个结论、留白 ≥30%…）
- `seed-des-05` 结构先于装饰（先写行动句与页标题清单，再排视觉）
- `seed-des-06` 评审清单而非意见（逐条报页码、违反的规则、最小修法）

全部是**可核验的检查项**，不含「你是一位…」。

### 面板：可选「成稿规范」开关

- 4 个可勾选规范：演示稿 / 文档 / 代码 / 文案
- 只传 **key**，措辞由 Host 掌握；未知 key 一律丢弃，无法注入指令
- 默认全不选，**此时系统提示词与 v1.8.0 逐字节一致**，质量基线不受影响
- 新增 `lib/standards.js` 纯函数模块，`looksLikePersona()` 与配套测试保证生成的追加段永不出现角色扮演措辞

### 验证

- 230 条测试（v1.8.0 为 211 条），新增 19 条
- 质量门禁 55.9 vs 51.6，无回退

## v1.8.0

**插件更名为「许愿树」（Wish Tree）**，从单个输入框按钮升级为独立面板，并新增提示词宝库。

### 更名

- 显示名、面板标题、图标、全部用户文案改为「许愿树 / Wish Tree」
- npm 包名由 `dsh-prompt-enhancer` 改为 **`dsh-wish-tree`**
- locale 命名空间改为 `dsh-wish-tree`
- 面板内保留一次旧名提示，说明「原名『增强提示词』」
- **迁移提示**：包名变了，已安装用户需重新安装一次（旧包不会自动迁移）；仓库地址仍为 `spycai/dsh-prompt-enhancer`

### 新增：独立面板

- 侧栏面板图标 + `main` 面板视图（不再只是一个按钮或浮层）
- 面板内含：想法输入区、场景与受众选项、「生成」主按钮、结果区（复制 / 一键回填）、宝库入口
- 保留输入框小按钮作为**第二入口**，避免侧栏入口在宿主变化时无路可进
- 延续 v1.7.0 的订阅策略：渲染期只存 `ref`，点击时才读会话消息

### 新增：提示词宝库

- 内置 **25 条精选种子**，覆盖 6 个分类（通用 / 写作 / 编程 / 分析 / 设计 / 学习），**离线完全可用**
- 支持显示、搜索（多关键词全匹配）、分类筛选、收藏
- 可从 GitHub 公开来源刷新扩充（`f/prompts.chat` 的 `prompts.csv`）
- 每条记录保存 `source` / `sourceUrl` / `license` / `fetchedAt`
- **许可白名单硬约束**：只接受 `CC0-1.0` / `MIT` / `Apache-2.0` / `BSD-3-Clause` / `ISC`，其余整条丢弃
- 选中条目可作为「参考范式」注入，模型只借鉴结构、不复制主题
- 刷新失败一律回落到内置种子库，只改提示文案，不影响可用性

### 新增：场景与受众

- 6 个场景（通用 / 写作 / 编程 / 分析 / 设计 / 学习），5 个受众选项
- 仅以 **key** 传给 Host，措辞由 Host 掌握；无法识别的 key 一律忽略，不注入任何指令
- 不选时（`general` / `auto`）追加内容为空，**系统提示词与 v1.7.0 逐字节一致**

### 修复 / 保持

- 不动 `lib/context.js`、`lib/timeout.js` 与既有 `enhance` 路由行为
- 质量门禁标准未降低：`baseline:check` 仍为 55.9 vs 51.6，无回退

### 测试

- 210 条（v1.7.0 为 119 条），新增 91 条
- 新增模块：`wishlist`（20）、`seed`（7）、`sources`（20）、`panel-state`（22）、`library-route`（8）、面板契约（7）
