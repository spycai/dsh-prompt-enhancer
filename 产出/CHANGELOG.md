## v1.8.8

按「生成之后那一段」的思路补齐四项能力。**未推送。**

前三个版本都在修「生成之前」和「生成失败」，但拿到结果之后仍有三个摩擦点：占位符要自己找、
不满意只能重来、好的存不下来。

### 1. 占位符变表单

生成结果里的 `[请补充：…]` 之前只写在后端规则里，前端零处理——用户得复制出去自己找括号。

现在 Host 在响应里直接返回 `placeholders` 与 `missing`，面板渲染成带标签的输入框，
填完实时替换进正文，**复制和回填都用填好的版本**。

关键决定：**占位符识别放在 Host**，不是前端各写一份。Client 无法 import ESM，若在前端实现就是
审计刚指出的「重复实现」问题重演。

未填的空白保留原括号，不会在句子里留洞。相同的标签合并成一个输入框，填一次替换所有出现位置。

### 2. 结果微调

结果下方新增三个快捷按钮（再短一点 / 更正式 / 加硬性约束）和一个自由输入框。

技术上走 `refineOf`：把**当前结果**作为 `current_prompt` 数据块、调整要求作为
`change_request` 数据块，两者都用 nonce 标签包裹。所以是「编辑现有的」，不是「从想法重推」——
后者会把上一版做过的所有决定全部丢掉，「压到 8 页」会返回一份不同的提示词，而不是更短的。

微调后保留仍然存在的空白填写值，其余清空。

### 3. 存入我的宝库

结果区新增「存入我的宝库」，写到 `<profile>/.dsh-wish-tree/personal.json`。

- **和远程缓存分开存**：刷新只覆盖缓存，绝不动个人库
- 列表里**个人条目排最前**，因为这是唯一不能重新拉取的数据
- 相同正文拒绝重复存入（按两次保存通常是确认，不是想要两份）
- 上限 200 条；标题自动从正文首句派生，不弹命名对话框

### 4. 自检提示

结果下方显示「目标、格式、受众、约束都齐了」或「还缺：受众 / 主要约束」。

检查的是**输出**（生成出来的提示词），不是用户的输入——让人知道这份提示词弱在哪，而不是盲信。

### 验证

- 302 条测试（v1.8.7 为 266 条）：placeholders 18 + personal 13 + refine 集成 5
- 质量门禁 55.9 vs 51.6，无回退
- 个人库端到端实测：存入 / 重复拒绝 / 列表置顶 / 删除四条路径都通
- 真机重载：三条路由均 401（存在），缓存 148 条未受影响

**未推送**（按用户要求，等待批准）。

## v1.8.5

修复 v1.8.4 之后仍然「刷新没东西」的问题。真实错误是
`cannot get property "profileDir" without inject`。

### 根因

`resolveProfileDir` 里写了 `ctx?.profileDir`，而 Cordis 里这些是**注入服务代理**——
未声明 `inject` 就访问会**直接抛异常**，不是返回 `undefined`。宝库每次请求都在这一行崩掉，
而数据一直好好躺在磁盘上。

（v1.8.4 把 `failureOutcome` 的通用兜底暴露成了 `The model call failed.`，误导了排查方向。）

### 修复

- 改用 `ctx.get(name)` 并全程包 `try`，不再访问任何 ctx 属性；拿不到就回退到
  `~/.dsh/profiles/desktop`。
- 两个 handler 全部包进 `try`（原来 `libraryPayload` 在 try 外，抛错变成未捕获拒绝）。
- 失败响应带 `error.name` 与 `message` 首行，不再被包成通用文案。
- 面板内联 34 条兜底种子，路由不通时也有内容可看，不再是空白。
- 加了用 Proxy 模拟注入代理的回归测试。

### 验证

- 270 条测试，质量门禁无回退

## v1.8.4

用户反馈：点「刷新」宝库没有东西。

### 根因

宝库路由**只有一条** /api/wish-tree/library，而改写路由一直有两条
（/api/... + /prompt-enhance）。当页面上下文打不通 /api/... 时，
宝库没有任何回退路径，而 .catch 是空的 —— 错误被完全吞掉，用户看到的就是空白。

面板的 `records` 初始值是 `[]`，所以 list 一失败，宝库直接是空的，连「没有匹配」
都算不上，就是「没有东西」。

### 修复

1. **加第二条路由** `/wish-tree-library`（webServer），与改写路由对齐，
   同样走 `connection.admit` 鉴权。
2. **前端探两路径**：新增 `postLibrary`，先试 `/api/...` 再回退，
   成功后记住可用路径。
3. **错误必须可见**：去掉静默 `.catch`，失败原因写进 `libNotice`
   （如「提示词宝库路由未响应（HTTP 404）」）。
4. **空态区分**：宝库完全没加载时显示「宝库没有加载成功 —— 请点「刷新」重试」，
   而不是误导性的「没有匹配的条目」。

### 验证

- 266 条测试（v1.8.3 为 265 条）
- 真机确认两条路由均在线（HTTP 401 = 需会话，路由存在）

## v1.8.2

用户反馈：面板点「生成」后很久没有反应。

排查结论：**不是卡死，是模型慢**。当前用的 `hy4free` 在 profile 里声明为
`supportedEfforts: [high]`、`canDisableThinking: false` —— 只能以最高强度思考且无法关闭，
慢是模型自身限制，插件侧无参数可调。

但等待期零反馈是真实缺陷：按钮只显示「生成中…」，240 秒内没有任何变化，用户无法区分
「正在跑」和「已卡死」。

### 修复

- 按钮显示**已等待秒数**（`生成中… 12s`）
- 等待超过 30 秒时提示「该模型思考较慢且无法调快，可换模型或继续等待」
- 等待期间提供**取消按钮**
- 计时器仅在 `busy` 时运行，请求结束立即清理

### 建议

若追求速度，换非推理模型（如 DeepSeek 系列）；若坚持用推理模型，可试 `hy4std`
并把 `reasoningEffort` 设为 `low`（它支持 low，`hy4free` 不支持）。

### 验证

- 232 条测试（v1.8.1 为 230 条）
- 质量门禁 55.9 vs 51.6，无回退
