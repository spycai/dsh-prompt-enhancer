# 许愿式提词 v2：先写后调

取代：`许愿式提词升级方案-v1.md`
基线：dsh-prompt-enhancer v1.5.4
日期：2026-11-14

---

## 0. 为什么推翻 v1

v1 把「细节追问」当成方案核心，这是一个用户体验上的误判。

### 0.1 三条反驳

**1. 新手回答抽象问题的能力很弱，判断具体产物的能力很强**

「这份 PPT 讲给谁看？」——不懂行的人可能真的答不上来。但如果直接把一份具体提示词摆在他面前，他立刻能说「不对，我要讲产品不是汇报」。

**判断具体产物很容易，凭空描述需求很难。** v1 把难点放在了前面。

**2. 追问是在用户还没看到任何东西时先收费**

输入框里点一下魔法棒，先等 2 秒分析，再回答问题，再等 3 秒生成。总耗时可能是 v1.5.4 的两倍，而用户此刻手里还是空的。

**3. 两段式是技术上的自洽，不是体验上的自洽**

把"分析"和"合成"拆开，工程上干净（可缓存、可测），但用户不关心这个。用户只关心：点一下，多久拿到能用的东西。

### 0.2 v1 还有三处过度设计

| v1 设计 | 问题 |
|---|---|
| few-shot 注入自学习 | 冷启动 20-30 次内完全无效，还引入隐私顾虑 |
| 自动画像（从行为信号推断偏好） | 「发送前编辑过」噪声极大——可能只是改了个错别字 |
| 每日归并 profile | 没数据时纯空转 |

## 1. 核心转向：让产物本身成为提问

```
v1:  草稿 → 分析 → [可能追问] → 合成 → 结果
                    ↑ 阻塞点

v2:  草稿 → 单次调用 → 结果 + 决定条 + 占位符（全部可改）
                        ↑ 零阻塞、零额外等待
```

三条不可让步的约束：

1. **第一次点击必须立即产出完整提示词**，速度与 v1.5.4 持平
2. **任何需要用户决策的点，都出现在产物之后**，不在之前
3. **改一个决定只重算这一项**，不重跑整条链路

---

## 2. 三分类：替代「追问机制」

v1 用四象限判断"该不该问"。v2 干脆**分成三类，一类都不打断**。

### 2.1 A 类 · 可决定（形式问题）

**特征**：属于专业判断，有主流默认值，选错也能用。

技术栈、页数、结构、篇幅、语气、图表类型、文件格式。

**处理**：自己决定 → 写进提示词 → 在决定条里显示为可点 chip。

```
决定：受众=同事 · 页数=10 · 风格=简洁
                          ↑ 每个都能点开换
```

选中后重算该项，其余不变。

### 2.2 B 类 · 不可决定（内容缺口）

**特征**：需要外部事实，无法合理虚构；编造即产生错误内容。

主题、数据、账号、日期、公司名、文件路径、引用来源。

**处理**：不是"问"，而是**在提示词正文里用醒目占位符**。

```
请制作一份关于〔主题：请填写〕的 PPT，面向公司内部同事，
共 10 页，风格简洁商务……
```

占位符高亮，点击聚焦到该位置直接输入。

**为什么比弹框问更好**：用户看到的是完整句子，知道这个信息在什么语境下用、填进去长什么样。弹框问"主题是什么"是脱离语境的。

### 2.3 C 类 · 高影响分叉

**特征**：两条解释都合理，且产出的提示词差异很大。

例：「做个方案」→ 商业方案 vs 技术方案，结构完全不同。

**处理**：给**两个完整候选**二选一，不是问"你要哪种方案"。

> 选择题永远比问答题好答。给两份具体的东西二选一，比让人凭空描述需求容易得多。

**触发阈值要严**：误触发会让用户烦。约束：单次只出 1 组分叉，且判定为 C 的请求占比 ≤15%。

### 2.4 三类都不阻塞的证明

| 用户行为 | 结果 |
|---|---|
| 点一下就发送 | 用 A 类默认 + B 类占位符，正常可用 |
| 只改一个 chip | 重算该项，其他不变 |
| 填了占位符 | 直接改文本，不重算 |
| 什么都不做 | 结果已就绪，可发送 |

**没有一条路径需要先回答才能拿到结果。**

## 3. 单次调用同时产出三段

### 3.1 输出协议

模型按固定结构输出（`###` 分隔，解析容错）：

```
### PROMPT
请制作一份关于〔主题：请填写〕的 PPT……

### DECISIONS
[{"slot":"audience","label":"受众","value":"同事",
  "options":["同事","客户","领导汇报"]},
 {"slot":"pages","label":"页数","value":"10",
  "options":["5","10","15","20"]}]

### PLACEHOLDERS
[{"slot":"topic","label":"主题","hint":"这份 PPT 讲什么"}]
```

### 3.2 解析与降级

| 情况 | 行为 |
|---|---|
| 三段齐全 | 正常拆分渲染 |
| 只有 `### PROMPT` | 正文进草稿，无 chips、无占位 |
| 完全解析不出 | **整段当正文**，等价 v1.5.4 |
| 模型忽略格式 | 同上，用户无感 |

**降级永不报错**——这是硬要求。格式是增强，不是依赖。

### 3.3 为什么不流式

流式的首字更快，但三段结构需要整体解析才能分离正文与元数据，流式会把结构标记暴露给用户。折中：等完整响应（通常 2-4s），但**只有一次往返**，总时长与 v1.5.4 相同。

## 4. 交互流程

### 4.1 主路径

```
1. 用户输入「做个PPT」
2. 点 ✨  → 按钮转圈（单次调用）
3. 草稿被替换为完整提示词（含高亮占位符）
4. 草稿下方出现一行：
   ┌────────────────────────────────────┐
   │ 受众=同事 ▾  页数=10 ▾  风格=简洁 ▾ │
   └────────────────────────────────────┘
5. 显示 ↩ 恢复（120s，沿用现有逻辑）
6. 用户直接发送 → 记录 feedback
```

### 4.2 C 类分叉路径

```
3'. 结果上方出现两个候选缩略：
    ┌──────────┬──────────┐
    │ 商业方案  │ 技术方案  │
    └──────────┴──────────┘
    默认选中第一个，直接可发送
```

### 4.3 改 chip 路径

```
1. 点「受众=同事 ▾」
2. 下拉选「客户」
3. 只重算受众相关的措辞（局部替换或重新生成，取快的那条）
4. 其余 chip 状态保留
```

## 5. 评估标准

### 5.1 北极星指标

```
首次命中率 = 改写后未编辑直接发送的次数 / 总改写次数
```

**这是唯一能证明"许愿式"有效的数字。** 目标：基线 → **≥60%**。

所有其他指标都是代理指标，只有这个直接反映用户体验。

### 5.2 维度表

| 维度 | 判定依据 | 阈值 | 自动化 |
|---|---|---|---|
| **D3 事实保真** | 数字/日期/URL/@mention/文件名保留率 | **100%，零篡改** | ✅ 规则 |
| **D7 下游可用性** | 把结果真的发给模型产出骨架，人工判可用性 | 抽样 20 条，≥80% 可用 | ⚠️ 抽样 |
| D6 意图一致 | 改写目标是否等同原任务 | 抽样 ≥95% | ❌ 抽样 + LLM 预筛 |
| D2 结构完整 | 目标/交付物/格式/约束/受众 覆盖 | ≥4/5，前两项必存 | ✅ |
| D1 可发送性 | 占位符数量与是否阻塞关键槽 | ≤2 且不含目标/交付物 | ✅ |
| D4 新手可用 | A 类决定是否全部可见可改 | 覆盖率 100% | ✅ |
| D5 无冗余 | 长度比 + 套话黑名单 | 命中黑名单 = 失败 | ✅ |

**砍掉 v1 的「术语密度」**：难以判定，容易自欺。

**D7 是新增的关键项**：其他指标都在评价"提示词看起来好不好"，只有 D7 回答"用它产出的东西能不能用"。

### 5.3 评分卡

```
score = 25·D3(保真) + 20·D7(下游可用) + 20·D6(意图) + 15·D2(完整) + 10·D1(可发送) + 10·D4(可用性)
```

保真与下游可用合计 45 分——**这两条错了，改写就是负价值**。

### 5.4 基线必须先建

W1 第一件事不是写代码，是**测出当前 v1.5.4 的首次命中率和 D7 得分**。没有基线，后面所有"提升了多少"都是空话。

## 6. 记忆：从显式开始

### 6.1 只记用户明确说过的

```
记录内容：用户点选过的 chip 答案
  { "audience": {"clients": 5, "management": 2} }
```

**不记推断**。行为信号（编辑、撤销）只用于评估，**不用于自动改默认值**——噪声太大。

### 6.2 生效条件

- 同一槽位同一答案出现 **≥3 次** 才作为默认
- 用户可一键清空
- 本地存储，不上传

### 6.3 few-shot 延后

攒够 50 条「首次命中」样本后再启用，搬到 v2.2。先有数据，再谈学习。

## 7. 研发计划：4 周

| 周 | 任务 | 验收标准 |
|---|---|---|
| **W1** | ① 先测 v1.5.4 基线（首次命中率 + D7）<br>② 结构化单调用 + 三段解析<br>③ 解析失败降级 | 同速不退化（±10%）；降级路径零报错；基线数据落盘 |
| **W2** | ① 决定 chips（点开可改）<br>② 占位符高亮 + 点击聚焦<br>③ 改 chip 只重算该项 | A/B 两类全不阻塞；chip 改动响应 <2s |
| **W3** | ① C 类分叉判定<br>② 双候选渲染与切换 | C 类占比 ≤15%；切换不重跑整链 |
| **W4** | ① 显式偏好记忆<br>② 下游可用性抽样流程<br>③ 40 条评估集 | 首次命中率相对基线 +15pt；D3 零失败 |

### 7.1 与 v1 计划的对比

| | v1 | v2 |
|---|---|---|
| 周期 | 5.5 周 | **4 周** |
| 第一次点击延迟 | +1~2s | **0** |
| 阻塞点 | 有（追问） | **无** |
| 学习模块 | 3 个文件 + 归并 | **1 个（显式记忆）** |
| 核心指标 | 六维度评分 | 六维度 + **首次命中率 + 下游可用性** |

### 7.2 风险

| 风险 | 对策 |
|---|---|
| 模型不遵守三段格式 | 解析失败整段当正文，永不报错；实测算失败率，>10% 则改协议 |
| 占位符被忽略直接发送 | 发送前不拦截，但发送后若仍是占位符状态，卡片提示「还有 1 处待填」 |
| chips 太多变噪音 | 最多 3 个；只显示影响大的 |
| D7 抽样太贵 | W4 只做 20 条，后续按月度抽查 |

## 8. 设计决策记录

| 决策 | 理由 | 被否方案 |
|---|---|---|
| 先写后调 | 用户判断产物能力强于描述需求能力 | 先问后写（v1） |
| 单次调用出三段 | 零额外延迟 | 两段式（v1） |
| 内容缺口用占位符不用提问 | 用户在语境里填，比抽象提问好答 | 弹框询问 |
| 分叉给两个完整候选 | 选择题比问答题好答 | 问"你要哪种" |
| 学习只记显式选择 | 行为信号噪声大，易学错 | 自动画像（v1） |
| 解析失败当正文 | 格式是增强不是依赖 | 报错提示"格式异常" |
| 先建基线再优化 | 无基线则"提升"不可验证 | 直接开发 |
