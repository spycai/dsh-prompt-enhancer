# 基线报告：v1.5.4 → v1.5.5

日期：2026-11-14
用例：`test/fixtures/wish-cases.json`（40 条，5 类）
评分器：`test/lib/evaluate.mjs`（纯规则）
运行器：`test/lib/baseline.mjs`
门禁：`test/golden-baseline.test.mjs` + `npm run baseline:check`

---

## 一、数据性质（先看这段）

**这不是插件端到端实测。** 插件走 `ctx.llm`，鉴权在 Host 进程内，外部脚本拿不到会话凭证（`/prompt-enhance` 与 `/api/prompt-enhancer/enhance` 均返回 401）。

所以采用**代理采集**：把 `lib/prompt.js` 里 `SYSTEM_PROMPTS.rewrite` 的**原文一字不改**交给独立执行体，对 40 条用例逐条产出改写结果。

| 项 | 状态 |
|---|---|
| 系统提示词 | 与对应版本完全一致（原文照搬） |
| 输入用例 | 40 条固定 fixture |
| 模型 | 代理执行体，**不等于**插件实际路由的 provider/model |
| 可比性 | 两版用同一套 fixture、同一评分器、同一采集口径 → **方向可信** |
| 绝对分 | **不可外推**，不能对外宣称"质量 55.9 分" |

另外：确定性满分只有 **60**。D6（意图一致）与 D7（下游可用性）需抽样人工判定，评分器**刻意不给这两项送分**。

## 三、改了什么

只动了 `lib/prompt.js` 的 `SYSTEM_PROMPTS.rewrite`，四条规则：

| 规则 | 原问题（基线实证） | 改法 |
|---|---|---|
| 3 | 写着"不要编造 audience"，与规则 6"保留数据暗示的受众"直接冲突 → 受众缺失 12 次 | 明确：受众/篇幅/语气**不是**用户私有事实，是**应当做出的假设**，但必须按规则 4 标注 |
| 4 | 只列技术选型（框架/存储/测试），不含受众、篇幅、结构、语气 | 扩展：这些同样属于"由你决定" |
| **4a（新增）** | 默认标注只有 77.5%，medium-vague 仅 30% | **每次输出至少一个 `[默认：…]` 标注** |
| 6 | "keep the audience, tone and scope the data implies"——数据没暗示时就不写 | 改为**四要素必须出现**：目标、交付物与格式、给谁、主要约束 |
| 7 | "紧凑"被用来当省略结构的理由 | 补一句：紧凑不能成为省略规则 6 的理由 |

## 四、方法论上的自我审查（重要）

这一轮我在**判断同一版修改的同时**调整了评分器，存在"调到通过"的风险。实际情况是评分器修了三轮，每一轮都由**真实输出与规则冲突**触发：

| 轮次 | 评分器 bug | 表现 |
|---|---|---|
| 1 | `goal` 只认「目标：」「请制作」，漏掉「做一份」「帮我做一份」 | 虚增 21 次失败 |
| 2 | `mustPlaceholder` 当成"全部命中"清单，语义应为"任一命中" | 正确追问被判失败 |
| 3 | `format` 不认「8–12 页」「800～1200 字」「文件清单」；`audience` 不认「使用者」「开发者」 | 结构完整被低估 |

**缓解措施**：
1. 最终数字由**同一版评分器同时重算 v1.5.4 与 v1.5.5**（51.6 vs 55.9），不是"新版用新尺、旧版用旧尺"
2. 稳定性锁定：`test/golden-baseline.test.mjs` 用精确值断言两个版本的分数
3. **待办（未完成）**：评分器冻结后，用一套新采集的独立样本复验，排除本轮调参偏差

**必须承认的局限**：第 3 条没做，所以 +4.3 分里有多少来自"评分器更懂中文表达"、多少来自"提示词真的更好"，目前分不开。结构完整率 +12.5pt 的方向应该可信（audience 缺失从 12 次降到 4 次是逐条数出来的），但精确幅度存疑。

## 六、门禁怎么用

```bash
npm test                 # 68 条，含评分器精确值锁定
npm run baseline:check   # 打分 + 与基线对比，回退即 exit 1
```

`baseline:check` 的判定：
- 任何维度跌幅超过 2pt → 失败
- 均分下跌 → 失败
- **保真率下跌零容忍** → 失败（改一个事实就比不改更糟）

改提示词的正确流程：
1. 改 `lib/prompt.js`
2. 用同一口径重新采集 `test/fixtures/recorded/<version>.json`
3. `node test/lib/baseline.mjs --outputs <新文件> --compare 产出/基线-v1.5.4-proxy.json`
4. 无回退才提交
