# 许愿树（Wish Tree）

写给不懂提示词工程的人：**写下一句想法，带走一份可以直接用的专业提示词。**

> 原名「增强提示词」。同一个插件，现在有独立面板和提示词宝库。
> 包名已改为 `dsh-wish-tree`，已安装的旧版需要重新安装一次。

**作者**：spycai <9680871@qq.com> · **许可证**：MIT

## 它能做什么

### 一句话变成专业提示词

在面板里写下想法（比如「下周给客户做产品演示，做个PPT」），按「生成」，得到一份结构完整、可以直接发给 AI 的提示词。

专业细节（格式、篇幅、结构、技术选型）由模型自己定主流方案，并标注成 `[默认：…，可改]`——**不需要你懂技术**。

### 三个入口

| 入口 | 位置 | 说明 |
|---|---|---|
| 侧栏面板图标 | 左侧栏面板列表 | **主入口**，打开完整面板 |
| 输入框小按钮 | 模型选择器左边 | 第二入口，功能相同 |
| 右键小按钮 | 同上 | 打开模式菜单（专业提示词 / 仅润色） |

### 场景与受众（可选）

- **场景**：通用 / 写作 / 编程 / 分析 / 设计 / 学习
- **受众**：自动判断 / 同事 / 客户 / 领导 / 大众

不选也能用。选了只是让提示词更贴合，**不会改变你的原意**。

### 成稿规范（可选，默认关）

面板里「成稿规范」一排可勾选：演示稿 / 文档 / 代码 / 文案。

**它加的是可核验的检查项，不是「你是一位资深专家」这类身份设定。** 例如演示稿规范写的是：

> 最多三种字号；每页一个结论且标题就是结论；正文不超过五行；每页留白 ≥30%；不用渐变、艺术字、剪贴画。

理由是：身份句**没有排除任何一个候选方案**（横版还是竖版、给谁看、几页，它一个都没决定），「大师」还容易让模型往视觉炫技方向走，反而牺牲 PPT 最需要的「每页一个结论」。而检查项能被模型执行、也能被你核验。

不选时系统提示词与上一版**逐字节一致**。宝库里另外内置了 3 条演示稿验收口径条目，可直接作为参考范式。

### 提示词宝库

内置 25 条精选提示词，覆盖 6 个分类，**断网也能用**。

- 搜索（多关键词）、按分类筛选、收藏
- 选中一条作为「参考范式」——模型借鉴它的**结构**，但写的是**你的**需求
- 点「刷新」可立即联网扩充；**默认每 6 小时自动刷新一次**（`autoRefreshHours`，0 关闭）
- 拉到的内容**存进本地缓存**，重启后仍然在，不会退回 25 条种子
- 刷新失败会自动回落到已有内容，不影响使用

**纯中文，单一数据源，CC0 公有领域：**

| 源 | 格式 | 许可 |
|---|---|---|
| `Vipuser2023/chatgpt-prompts-chinese` | JSON | CC0-1.0 |

内置 25 条种子与所有联网条目**全部是中文**。库里有语言闸门，非中文记录一律丢弃，
即使将来加回英文源也不会出现在面板里。

只按 raw 地址取结构化文件，**不解析 HTML、不写爬虫、无需鉴权**。缓存位置：
`<profile>/.dsh-wish-tree/library.json`。

### 它会读最近的对话

点生成时，插件会带上本会话最近 8 条消息（最多 4000 字）作为背景，让改写知道前文已经说清的受众、项目与约束。

背景**只作参考**——与你当前输入冲突时，一律以当前输入为准。

## 它怎么工作（关于你的 API 密钥）

**这个插件不自带模型，也不接触你的 API 密钥。**

它调用 DSH 宿主提供的 `ctx.llm.stream({ provider, model, ... })`，用你**当前会话正在使用的模型**做改写。凭证由 DSH 自己持有，插件只传入「provider/model 名字 + 文本」。

网络请求只发往**本机**的 `/api/...`，以及你主动点「刷新」时从 GitHub 取公开提示词数据。

## 提示词的来源与许可

宝库**只收录允许再分发的**内容：

| 来源 | 许可 | 说明 |
|---|---|---|
| 内置种子（25 条） | CC0-1.0 | 依据 `f/prompts.chat` 的提示词数据许可 |

| 在线刷新 | CC0-1.0 | `Vipuser2023/chatgpt-prompts-chinese` 的 `prompts-zh.json` |

插件内置**许可白名单**（`CC0-1.0` / `MIT` / `Apache-2.0` / `BSD-3-Clause` / `ISC`），不在名单内的条目**整条丢弃**，不会出现在面板里。每条记录都保存来源与许可字段。

## 配置

`cordis.patch.yml` 里 9 个可选字段（都有默认值）：

`mode`、`maxTokens`、`temperature`、`reasoningEffort`、`maxInputChars`、`maxOutputChars`、`rateLimitPerMinute`、`provider`、`model`

**改写很慢时先把 `reasoningEffort` 设成 `low`**，再考虑换模型——推理模型的思考 token 也计入 `maxTokens`，所以默认值给了 4000。

## 开发

```bash
npm test              # 自动发现并运行 test/*.test.mjs（当前 265 条）
npm run baseline:check # 提示词质量门禁：回退即失败
```

Host 半在 `index.js`（路由、鉴权、模型调用），Client 半在 `client.js`（面板、按钮、宝库 UI），纯逻辑在 `lib/`：

| 模块 | 职责 |
|---|---|
| `lib/prompt.js` | 提示词文本、配置、场景/受众注入、参考范式注入 |
| `lib/context.js` | 对话上下文整形 |
| `lib/timeout.js` | 超时策略 |
| `lib/wishlist.js` | 宝库数据模型、许可白名单、搜索收藏 |
| `lib/seed.js` | 内置种子库 |
| `lib/sources.js` | 联网取数、CSV 解析、降级 |
| `lib/panel-state.js` | 面板状态机 |
| `lib/standards.js` | 可选的成稿验收规范（非身份设定） |
| `lib/library-cache.js` | 宝库本地缓存（落库） |

质量基线、评估器与录制样本在 `test/lib/` 与 `test/fixtures/`。
